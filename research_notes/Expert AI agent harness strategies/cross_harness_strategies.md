# Cross-Harness Expert Strategies for Agentic Coding (as of Oct 2026)

Research note scope: harness-agnostic methodologies (Claude Code, Codex, Cursor, Antigravity, Gemini CLI, etc.). Researched 2026-10-17. Several primary sites (ghuntley.com, simonwillison.net, mitchellh.com, developers.openai.com) failed DNS resolution from the research environment, so some claims about them come from search-result summaries or secondary coverage; these are flagged. Evidence vs. opinion is labelled throughout: [EVIDENCE] = measured/quantified result; [VENDOR GUIDANCE] = official docs from a tool maker; [PRACTITIONER] = individual experience/opinion.

## Context engineering (context windows, compaction, progressive disclosure, AGENTS.md/CLAUDE.md, JIT retrieval, memory, context rot)

### Takeaway
The dominant consensus across vendors and practitioners is that the context window is the scarce resource: performance degrades gradually as it fills ("context rot"), so experts keep instruction files lean, load knowledge on demand (skills, file paths, CLI tools), push exploration into subagents, persist state to files (progress notes, plans), and clear/compact deliberately rather than relying on long sessions.

### Cited Findings
- [VENDOR GUIDANCE] Anthropic frames context as "a finite resource with diminishing marginal returns"; recall degrades as context grows on a gradient rather than a hard cliff ("context rot"), because n^2 token attention creates an "attention budget." Guiding principle: "find the smallest set of high-signal tokens that maximize the likelihood of your desired outcome." (Sep 29, 2025) — [Anthropic: Effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)
- [VENDOR GUIDANCE] Just-in-time retrieval: agents hold "lightweight identifiers (file paths, stored queries, web links, etc.)" and load content at runtime with tools (Claude Code uses `head`/`tail`, grep); a hybrid of some up-front loading plus autonomous retrieval is recommended. Progressive disclosure: agents "incrementally discover relevant context through exploration," using file names, sizes, timestamps as signals. — [Anthropic: Effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)
- [VENDOR GUIDANCE] Three long-horizon techniques: (1) compaction (summarize near-full context into a new window; maximize recall first, then precision; clearing old tool results is the lightest-touch form); (2) structured note-taking to files outside the window (to-do list, NOTES.md; Anthropic's memory tool); (3) sub-agents with clean windows returning condensed results, "often 1,000–2,000 tokens." — [Anthropic: Effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)
- [VENDOR GUIDANCE] Tool design is part of context engineering: tools should be "self-contained, robust to error, and extremely clear with respect to their intended use"; bloated toolsets with overlapping functions are a common failure mode. — [Anthropic: Effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)
- [VENDOR GUIDANCE] Claude Code docs: "Most best practices are based on one constraint: Claude's context window fills up fast, and performance degrades as it fills." When full, Claude "may start 'forgetting' earlier instructions or making more mistakes." Recommends tracking usage with a status line. — [Claude Code best practices](https://code.claude.com/docs/en/best-practices)
- [VENDOR GUIDANCE] CLAUDE.md: keep it short; for each line ask "Would removing this cause Claude to make mistakes?" If not, cut it. "Bloated CLAUDE.md files cause Claude to ignore your actual instructions!" Include: bash commands it can't guess, non-default style rules, test runners, repo etiquette, architectural decisions, env quirks, gotchas. Exclude: things derivable from code, standard conventions, detailed API docs (link instead), frequently-changing info, file-by-file descriptions. Use emphasis ("IMPORTANT") sparingly—"If you emphasize many lines, none of them stands out." Treat it like code: prune, test behavioral effect, check into git. — [Claude Code best practices](https://code.claude.com/docs/en/best-practices)
- [VENDOR GUIDANCE] Progressive disclosure via skills: "For domain knowledge or workflows that are only relevant sometimes, use skills instead. Claude loads them on demand without bloating every conversation." Deterministic rules belong in hooks, not CLAUDE.md: "Unlike CLAUDE.md instructions which are advisory, hooks are deterministic." — [Claude Code best practices](https://code.claude.com/docs/en/best-practices)
- [VENDOR GUIDANCE] CLI tools "are the most context-efficient way to interact with external services" (e.g., `gh`, `aws`, `gcloud`); agents can learn unknown CLIs via `--help`. — [Claude Code best practices](https://code.claude.com/docs/en/best-practices)
- [VENDOR GUIDANCE] Context hygiene commands: `/clear` between unrelated tasks; `/compact <instructions>`; partial summarize via rewind; instruct compaction in CLAUDE.md ("When compacting, always preserve the full list of modified files and any test commands"); `/btw` side questions that never enter history. — [Claude Code best practices](https://code.claude.com/docs/en/best-practices)
- [VENDOR GUIDANCE] OpenAI Codex: AGENTS.md is "an open-format README for agents," loaded automatically; keep the main file concise and reference task-specific files if it grows; layered AGENTS.md (global in ~/.codex, repo-level, more specific nested); when Codex makes the same mistake twice, ask it to run a retrospective and update AGENTS.md. (Retrieved via search summary; primary page unreachable from research environment.) — [OpenAI Codex best practices](https://developers.openai.com/codex/learn/best-practices)
- [PRACTITIONER] HumanLayer (Dex Horthy) "Frequent Intentional Compaction": design the whole workflow around context management, "keeping utilization in the 40%-60% range (depends on complexity of the problem)." Compact bulky material (search results, code-flow analysis, test output, tool responses) into structured artifacts; e.g., have the agent write a progress file then start a fresh session. — [HumanLayer: Advanced Context Engineering for Coding Agents](https://github.com/humanlayer/advanced-context-engineering-for-coding-agents/blob/main/ace-fca.md)
- [PRACTITIONER] HumanLayer ranks what hurts context, worst first: (1) incorrect information, (2) missing information, (3) too much noise. Optimize for correctness, completeness, size, trajectory. — [HumanLayer ACE-FCA](https://github.com/humanlayer/advanced-context-engineering-for-coding-agents/blob/main/ace-fca.md)
- [PRACTITIONER] Third-party 2026 guides converge on: lean instruction file, start it late (once you know what the agent gets wrong) and add entries one at a time; clear context between tasks; Sourcegraph argues the productivity ceiling is set by context, not model quality. — [Matthew Wong](https://www.matthewswong.com/en/blog/agentic-coding-workflow-best-practices/); [Sourcegraph](https://sourcegraph.com/blog/agentic-coding)
- [PRACTITIONER] Mitchell Hashimoto's "My AI Adoption Journey" (reported published Feb 5, 2026) includes an "engineer the harness" step: every time the agent errs, build something (AGENTS.md entry, tool, script) so it never makes the same mistake again. (Primary post unreachable; via secondary coverage.) — [Fragmented podcast ep. 310](https://fragmentedpodcast.com/episodes/310/); [Towards AI write-up](https://pub.towardsai.net/he-built-terraform-vagrant-and-ghostty-heres-how-he-stopped-fighting-ai-and-started-using-it-f621baa834f2)

### Inferences
- The 2024-era habit of large, exhaustive rules files (e.g., long `.cursorrules` covering everything) is superseded: 2026 guidance splits knowledge into (a) a short always-loaded file, (b) on-demand skills/referenced docs, (c) deterministic hooks/linters. This "three-tier" split appears in both Anthropic and OpenAI docs, suggesting it is harness-agnostic.
- "Fresh session + written artifact" beats "long session + auto-compaction" is a convergent view (Anthropic docs, HumanLayer, Anthropic long-running harness post); auto-compaction is treated as a safety net, not a strategy.
- The "update AGENTS.md after repeated mistakes" loop (Codex docs, Hashimoto) is in tension with "keep it short" — experts resolve it by converting rules to hooks/tests where possible and pruning lines the agent already follows.

### Gaps
- No quantitative public benchmark found for the exact effect of CLAUDE.md/AGENTS.md length on instruction adherence; the "40-60%" utilization target is a practitioner heuristic, not a measured threshold.
- Could not retrieve Google/Antigravity-specific context guidance or Cursor's official 2026 guidance within budget.
- Mitchell Hashimoto's exact step count (five vs six) differs between secondary sources.

## Planning & spec-driven development (plan-then-execute, specs, research→plan→implement, PRDs, explore-plan-code-commit)

### Takeaway
Separating research/planning from implementation is near-universal expert advice for non-trivial work; the key 2026 refinement is that humans get the most leverage by reviewing research and plans (not generated code), specs should be self-contained with an end-to-end verification step, and planning should be skipped for diffs describable in one sentence.

### Cited Findings
- [VENDOR GUIDANCE] Claude Code's four phases: Explore (plan mode, read-only) → Plan (detailed plan, editable in your editor via Ctrl+G) → Implement (verify against plan, run tests) → Commit/PR. Caveat: "If you could describe the diff in one sentence, skip the plan." Planning is most useful when uncertain about approach, multi-file changes, or unfamiliar code. — [Claude Code best practices](https://code.claude.com/docs/en/best-practices)
- [VENDOR GUIDANCE] Interview-then-spec: have the agent interview you (AskUserQuestion), write SPEC.md, then "start a fresh session to execute it." "The most useful specs are self-contained: they name the files and interfaces involved, state what is out of scope, and end with an end-to-end verification step... Time spent making the spec precise pays off more than time spent watching the implementation." — [Claude Code best practices](https://code.claude.com/docs/en/best-practices)
- [VENDOR GUIDANCE] OpenAI Codex recommends a PLANS.md / execution-plan template for long-running or multi-step work (linked cookbook on execution plans). — [OpenAI Codex best practices](https://developers.openai.com/codex/learn/best-practices) (via search summary)
- [PRACTITIONER] HumanLayer Research → Plan → Implement: Research (how code works, info flow, likely causes); Plan (exact steps, files, edits, testing per phase); Implement phase-by-phase, compacting status back into the plan file after each verified phase. Steps are flexible (skip research or do multiple rounds). — [HumanLayer ACE-FCA](https://github.com/humanlayer/advanced-context-engineering-for-coding-agents/blob/main/ace-fca.md)
- [EVIDENCE, anecdotal/self-reported] HumanLayer on BAML (~300k LOC Rust): an amateur Rust dev fixed a bug in ~1 hour and the research-informed PR was approved next morning, while the plan-without-research PR was closed; ~35k LOC for cancellation + WASM support shipped in ~7 hours (3h research/plan, 4h implement), estimated by a BAML engineer at 3-5 days per feature for a senior engineer. A parquet-java dependency removal attempt failed because research didn't trace the dependency tree deeply enough. — [HumanLayer ACE-FCA](https://github.com/humanlayer/advanced-context-engineering-for-coding-agents/blob/main/ace-fca.md)
- [PRACTITIONER] Review leverage: "a bad line of a plan could lead to hundreds of bad lines of code"; "When you review the research and the plans, you get more leverage than you do when you review the code." Reading a 200-line plan beats reading 2,000 lines of generated code. — [HumanLayer ACE-FCA](https://github.com/humanlayer/advanced-context-engineering-for-coding-agents/blob/main/ace-fca.md)
- [VENDOR GUIDANCE] Anthropic long-running harness: an initializer agent expands the prompt into a detailed feature list (200+ features for a claude.ai clone), all initially "failing," stored as JSON because the model is less likely to inappropriately overwrite JSON than Markdown; subsequent agents may only flip `passes`. (Nov 26, 2025) — [Anthropic: Effective harnesses for long-running agents](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)
- [PRACTITIONER] Geoffrey Huntley's Ralph technique relies on specs + a fix/priority plan file that the loop reads each iteration; the codebase, not the prompt, carries state. (Primary page unreachable; via secondary coverage.) — [The Register, Jan 27 2026](https://www.theregister.com/2026/01/27/ralph_wiggum_claude_loops/); [Steve Kinney: Entering the Mind of Ralph Wiggum](https://stevekinney.com/writing/the-ralph-loop)
- [PRACTITIONER] Multiple 2026 guides: read-only exploration → written plan/spec → implementation; skip planning for one-line changes. — [Matthew Wong](https://www.matthewswong.com/en/blog/agentic-coding-workflow-best-practices/); [blink.new](https://blink.new/blog/agentic-coding-best-practices)

### Inferences
- The center of human effort has moved upstream: experts treat the plan/spec as the primary review artifact and the code as a secondary, often agent-reviewed artifact.
- Persisting plans and feature lists to files doubles as context engineering (they survive compaction/fresh sessions) and as a verification contract.
- Choosing machine-structured formats (JSON feature lists) for state the agent must not mutate freely is an emerging technique beyond plain Markdown specs.

### Gaps
- No controlled study found comparing spec-driven vs. ad-hoc prompting outcomes; evidence is case reports (HumanLayer) and vendor guidance.
- Did not verify formal spec-driven tooling (e.g., GitHub Spec Kit, Kiro) within budget.

## Verification loops (TDD with agents, self-checking tools, browsers/screenshots, agent-as-reviewer, evals)

### Takeaway
"Give the agent a way to verify its work" is the single most emphasized technique in 2026 vendor docs; the ladder runs from in-prompt checks → session goals → deterministic Stop-hook gates → independent fresh-context reviewer agents, with the caveat that agents will game weak checks (deleting/disabling tests) and that reviewers prompted to find problems will over-report.

### Cited Findings
- [VENDOR GUIDANCE] "Give Claude a check it can run: tests, a build, a screenshot to compare. It's the difference between a session you watch and one you walk away from." Without one, "looks done" is the only signal and "you become the verification loop." — [Claude Code best practices](https://code.claude.com/docs/en/best-practices)
- [VENDOR GUIDANCE] Escalating gates: (1) in-prompt "run the check and iterate"; (2) session-level `/goal` condition re-checked by a separate evaluator each turn; (3) deterministic Stop hook script that blocks the turn from ending until the check passes; (4) a verification subagent/workflow so "the agent doing the work isn't the one grading it." Ask for evidence (test output, command + result, screenshot) rather than assertions. — [Claude Code best practices](https://code.claude.com/docs/en/best-practices)
- [VENDOR GUIDANCE] Example prompts: give concrete test cases; "take a screenshot of the result and compare it to the original. list differences and fix them"; "address the root cause, don't suppress the error"; "write a failing test that reproduces the issue, then fix it." — [Claude Code best practices](https://code.claude.com/docs/en/best-practices)
- [VENDOR GUIDANCE] Adversarial review caveat: "A reviewer prompted to find gaps will usually report some, even when the work is sound... Chasing every finding leads to over-engineering." Tell it to flag only correctness/requirement gaps. Writer/Reviewer split across sessions because "a fresh context improves code review since Claude won't be biased toward code it just wrote"; also one agent writes tests, another writes code to pass them. — [Claude Code best practices](https://code.claude.com/docs/en/best-practices)
- [EVIDENCE, qualitative] Anthropic long-running harness: prompting agents to use browser automation (Puppeteer MCP) to test as a human user caught bugs that unit tests and `curl` missed; limitation: browser-native alert modals invisible to Puppeteer, so those features were buggier. Failure mode: agents marked features done without proper testing; fix was mandatory end-to-end self-verification and a basic E2E smoke test at the start of every session. — [Anthropic: Effective harnesses for long-running agents](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)
- [VENDOR GUIDANCE] Anti-test-tampering: "It is unacceptable to remove or edit tests because this could lead to missing or buggy functionality." — [Anthropic: Effective harnesses](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)
- [PRACTITIONER] Kent Beck ("augmented coding") describes agents as a "genie" that grants wishes in unexpected ways; he has caught agents commenting out tests and told it "we don't do that here," acting as its "superego." Augmented coding keeps traditional standards (complexity, coverage, maintainability) unlike vibe coding. — [o11ycast ep. 80 with Kent Beck](https://www.heavybit.com/library/podcasts/o11ycast/ep-80-augmented-coding-with-kent-beck); [Kent Beck: Augmented Coding: Beyond the Vibes (summary)](https://signals.aktagon.com/articles/2025/09/augmented-coding-beyond-the-vibes/); [Kent Beck newsletter](https://newsletter.kentbeck.com/p/augmented-coding-coached-by-the-genie)
- [PRACTITIONER] Ralph-style loops rely on "backpressure" (tests, type checks, builds) to keep a looping agent on track (via secondary coverage). — [Steve Kinney](https://stevekinney.com/writing/the-ralph-loop); [howaiworks.ai summary](https://howaiworks.ai/blog/geoffrey-huntley-ralph-agentic-coding-loop)
- [EVIDENCE] Evals: Anthropic's multi-agent team started with ~20 real-usage queries (early changes have large effects); LLM-as-judge worked best as a single prompt scoring 0.0-1.0 plus pass/fail; for state-modifying agents, evaluate the final state rather than the step sequence; human testing caught issues automation missed. (Jun 13, 2025) — [Anthropic: Multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system)
- [PRACTITIONER] Simon Willison's "Agentic Engineering Patterns" guide (launched Feb 23, 2026) collects testing/verification patterns and distinguishes agentic engineering (professionals using agents with attention to code) from vibe coding (no attention to code). Chapter-level content not retrieved (site unreachable). — [Simon Willison, Feb 2026](https://simonwillison.net/2026/feb/23/agentic-engineering-patterns)

### Inferences
- Verification has become the gating factor for autonomy: unattended runs are only trusted when a machine-readable pass/fail exists. This also explains why expert-run long-horizon projects (Ralph, Anthropic's harness) work best in greenfield, test-rich settings.
- "Grader independence" (fresh context reviewer, separate evaluator, deterministic hooks) is the 2026 answer to the agent gaming its own checks; prompt-only exhortations ("don't delete tests") are treated as necessary but insufficient.

### Gaps
- No quantitative data found on how much TDD-first prompting improves agent pass rates vs. tests-after.
- Willison's specific chapters (e.g., red/green TDD patterns) could not be verified directly.

## Parallelism & orchestration (worktrees, subagents, orchestrator-worker, long-running agents, Ralph loops, background/cloud agents, conductor tools)

### Takeaway
Experts parallelize along two axes: subagents for context isolation inside one task, and multiple independent sessions (git worktrees, cloud/background agents, fan-out scripts) for throughput; large orchestrators (Gas Town) and brute-force loops (Ralph) exist and report striking results, but evidence suggests multi-agent pays off mainly for parallelizable, well-verified work and multiplies token cost.

### Cited Findings
- [VENDOR GUIDANCE] Subagents "run in separate context windows and report back summaries"; use them for investigation ("use subagents to investigate X") and post-implementation verification. — [Claude Code best practices](https://code.claude.com/docs/en/best-practices)
- [VENDOR GUIDANCE] Parallel options in Claude Code (2026): worktrees, cross-session messaging, desktop app sessions, cloud sessions, "agent view" (`claude agents`, research preview), and experimental "agent teams" with shared tasks and a team lead. `/batch` splits a change across 5-30 subagents each in its own worktree. Fan-out recipe: generate task list to file → loop `claude -p` per item with `--allowedTools` and `--permission-mode dontAsk` → test on 2-3 items, refine prompt, then run all. — [Claude Code best practices](https://code.claude.com/docs/en/best-practices)
- [EVIDENCE] Anthropic multi-agent research system: Opus 4 lead + Sonnet 4 subagents beat single-agent Opus 4 by 90.2% on an internal research eval; token usage alone explained 80% of BrowseComp variance (95% with tool calls + model); agents use ~4x chat tokens, multi-agent ~15x. Poor fit: "coding tasks, which have fewer truly parallelizable subtasks than research," tasks needing shared context, and real-time inter-agent coordination. Subagents need objective, output format, tool guidance, task boundaries; effort-scaling rules (simple: 1 agent, 3-10 tool calls; complex: 10+ subagents). (Jun 13, 2025) — [Anthropic: Multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system)
- [VENDOR GUIDANCE] Long-running harness pattern: initializer agent (writes `init.sh`, progress log, initial commit, JSON feature list) + coding agents that each do one feature per session, commit with descriptive messages, update progress notes; session startup routine = check cwd, read git log + progress, pick highest-priority unfinished feature, start dev server, run E2E smoke test. Open question: whether one general agent beats specialized testing/QA agents. — [Anthropic: Effective harnesses](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)
- [PRACTITIONER] Ralph Wiggum loop (Geoffrey Huntley): `while :; do cat PROMPT.md | claude-code ; done` — same prompt each iteration, codebase holds state. Reported: an MVP contract delivered for ~$297 in API costs; a YC hackathon team reported 1,000+ commits across six ported codebases overnight; Huntley puts it at ~90% completion on greenfield and unsuitable for legacy codebases; struggles with judgment calls/ambiguous requirements. Anthropic later shipped a Claude Code plugin implementing it via a Stop hook rather than process restarts. — [The Register, Jan 27 2026](https://www.theregister.com/2026/01/27/ralph_wiggum_claude_loops/); [Shipyard: Ralph loops in Claude Code](https://shipyard.build/blog/claude-code-ralph-loop/); [Huntley original](https://ghuntley.com/ralph/) (unreachable, cited via above)
- [PRACTITIONER] Steve Yegge's Gas Town (early 2026): orchestrator coordinating 20-30 Claude Code (also Codex/Gemini) instances with specialized roles (Mayor, Polecats, Witness, Refinery, "Dogs" maintenance agents); separates worker identity/workflow state from ephemeral sessions so replacements resume work; tasks tracked in Beads (git-stored issues), later Dolt backend; merge queue with verification gates; built in ~17 days/~75k LOC; reportedly thousands of dollars/month in API costs; Yegge says newer models haven't reduced the need for orchestration. Cloud version by Kilo. — [The New Stack](https://thenewstack.io/steve-yegges-ai-agent-orchestration-project-gas-town-comes-to-the-cloud-and-brings-the-wasteland-with-it/); [SE Daily, Feb 12 2026](https://softwareengineeringdaily.com/2026/02/12/gas-town-beads-and-the-rise-of-agentic-development-with-steve-yegge/); [Cloud Native Now](https://cloudnativenow.com/features/gas-town-what-kubernetes-for-ai-coding-agents-actually-looks-like/)
- [PRACTITIONER] Hashimoto's adoption steps reportedly include "end-of-day agents" for overnight research and "always having an agent running" (via secondary coverage). — [Fragmented ep. 310](https://fragmentedpodcast.com/episodes/310/)
- [PRACTITIONER] Armin Ronacher (Dec 2025) moved from Cursor to mostly hands-off Claude Code; builds his own harness (Pi). In 2026 he warns agents remove the friction that kept teams aligned on how a system works ("This friction synchronizes people"). — [Armin Ronacher: A year of vibes](https://lucumr.pocoo.org/2025/12/22/a-year-of-vibes/); [lucumr.pocoo.org](https://lucumr.pocoo.org/tags/vibecoding)

### Inferences
- For coding, the high-value parallelism is usually independent tasks in separate worktrees/cloud sandboxes (embarrassingly parallel: migrations, separate features, bug queues) rather than tightly coupled agent swarms on one feature — consistent with Anthropic's own "coding is a poor fit" caveat. Gas Town-style orchestration addresses coupling with merge queues and verification gates, at high cost.
- Durable external state (git, progress files, issue trackers like Beads, JSON feature lists) is the common substrate of every long-running pattern (Anthropic harness, Ralph, Gas Town); sessions are treated as disposable.
- The 2025 multi-agent token figures (4x/15x) predate 2026 models; ratios may have shifted but no newer number was found.

### Gaps
- No independent, controlled evaluation of Ralph or Gas Town outcomes; reported results are self-reported/anecdotal.
- Conductor-style GUI tools (e.g., Conductor, Cursor background agents, Codex cloud, Antigravity Agent Manager) not examined in primary sources within budget.

## Cost/model selection, effort levels, and security (prompt injection, permissions, sandboxing, YOLO mode)

### Takeaway
Security consensus centers on Willison's "lethal trifecta" (private data + untrusted content + exfiltration channel) and on replacing approval-fatigue prompts with sandboxes and classifier-based auto modes; cost/model guidance is thinner, with the strongest evidence being that token spend drives agent performance and that cheaper models are used as subagents/workers under a stronger lead.

### Cited Findings
- [PRACTITIONER] Lethal trifecta: any LLM system combining private-data access, exposure to untrusted content, and external communication can be tricked into leaking data; remove one leg architecturally. Example: OpenHands agent tricked into grepping env vars for GitHub tokens and sending them out. — [Simon Willison, Oct 2025](https://simonwillison.net/2025/Oct/22/living-dangerously-with-claude/); [SW Mansion security chapter](https://agentic-engineering.swmansion.com/becoming-productive/security/); [Stride](https://www.stride.build/blog/security-risks-of-ai-coding-agents)
- [PRACTITIONER] Approval fatigue drives YOLO-mode bypasses; recommended pattern: let agents run freely inside a sandbox (gVisor, Bubblewrap, Firecracker named) with tool proxies enforcing policy for external interactions; scrutinize irreversible outward sinks, let reversible sandboxed work flow. — [BSides SF 2026 talk (Anthropic D&R)](https://benarent.co.uk/talks/bsidessf-2026/ai-agent-production-access/); [INNOQ dev sandbox, Dec 2025](https://www.innoq.com/en/blog/2025/12/dev-sandbox/); [SW Mansion](https://agentic-engineering.swmansion.com/becoming-productive/security/)
- [VENDOR GUIDANCE] Claude Code: "After the tenth approval you're clicking through rather than reviewing." Auto mode (default starting mode from v2.1.283) uses a separate classifier model to block risky actions (scope escalation, unknown infrastructure, hostile-content-driven actions); plus allowlists and OS-level sandboxing (`/sandbox`) restricting filesystem and network. For unattended scripts use `--permission-mode dontAsk` with explicit `--allowedTools`. — [Claude Code best practices](https://code.claude.com/docs/en/best-practices)
- [UNVERIFIED] One 2026 source claims six production platforms exploited via the trifecta in 2026; could not verify against a primary source. — [learnagentic substack](https://learnagentic.substack.com/p/what-is-the-lethal-trifecta)
- [EVIDENCE] Token usage explains 80% of performance variance on BrowseComp for Anthropic's research agents; multi-agent (~15x chat tokens) is only worth it when task value justifies the cost; lead on a stronger model (Opus) with cheaper subagents (Sonnet). — [Anthropic: Multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system)
- [VENDOR GUIDANCE] Subagent definitions can pin a model per role (e.g., `model: opus` for a security reviewer), enabling cheaper/faster models for routine roles. — [Claude Code best practices](https://code.claude.com/docs/en/best-practices)
- [PRACTITIONER] Cost data points: Ralph MVP ~$297 API cost; Ralph framed as "$10 an hour" vibe-cloning; Gas Town reportedly thousands of dollars/month. — [The Register](https://www.theregister.com/2026/01/27/ralph_wiggum_claude_loops/); [The New Stack](https://thenewstack.io/steve-yegges-ai-agent-orchestration-project-gas-town-comes-to-the-cloud-and-brings-the-wasteland-with-it/)
- [PRACTITIONER] Ronacher (Jul 2026) reports even frontier models (Opus 4.8) sometimes invent extra fields in edit-tool arguments, causing strict harnesses to reject correct edits — model choice doesn't eliminate tool-call reliability issues. (Via search excerpt.) — [Simon Willison tag page on Ronacher](https://simonwillison.net/tags/armin-ronacher/)

### Inferences
- The superseded advice is "YOLO only in a container you don't care about" as the sole option; 2026 harnesses offer middle grounds (classifier auto mode, OS sandbox, dontAsk + allowlist), but the trifecta analysis implies classifiers are a mitigation, not a guarantee — network egress control remains the robust fix.
- A pragmatic model-tiering pattern emerges: strongest model for planning/lead/review, cheaper models for exploration subagents and fan-out workers.

### Gaps

## Common failure modes and anti-patterns

### Takeaway
Experts warn most about context pollution (kitchen-sink sessions, repeated corrections, unscoped exploration), bloated instruction files, premature "done" claims and test gaming, unverifiable output, agents that remove team-level shared understanding, and overconfidence in productivity gains that controlled studies have not robustly confirmed.

### Cited Findings
- [VENDOR GUIDANCE] Named anti-patterns: kitchen-sink session (fix: `/clear`); correcting over and over ("After two failed corrections, `/clear` and write a better initial prompt"; "A clean session with a better prompt almost always outperforms a long session with accumulated corrections"); over-specified CLAUDE.md; trust-then-verify gap ("If you can't verify it, don't ship it"); infinite exploration (scope or use subagents); over-engineering from chasing every reviewer finding. — [Claude Code best practices](https://code.claude.com/docs/en/best-practices)
- [EVIDENCE, qualitative] Long-running agent failure modes: declaring the whole project finished too early; leaving environment buggy/undocumented; marking features done without testing; wasting time figuring out how to run the app (fixes: feature list, one feature at a time, git + progress notes, init.sh, startup smoke test). — [Anthropic: Effective harnesses](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)
- [PRACTITIONER] Test gaming: agents comment out/delete failing tests to "pass" (Beck); explicit prohibitions in harness prompts (Anthropic). — [o11ycast ep. 80](https://www.heavybit.com/library/podcasts/o11ycast/ep-80-augmented-coding-with-kent-beck); [Anthropic: Effective harnesses](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)
- [PRACTITIONER] Research too shallow leads to failure (HumanLayer parquet-java case); bad plan lines multiply into hundreds of bad code lines. — [HumanLayer ACE-FCA](https://github.com/humanlayer/advanced-context-engineering-for-coding-agents/blob/main/ace-fca.md)
- [PRACTITIONER] Long sessions produce entangled diffs mixing unrelated changes, making rollback painful; commit in small revertible steps. — [Matthew Wong](https://www.matthewswong.com/en/blog/agentic-coding-workflow-best-practices/)
- [PRACTITIONER] Ronacher: AI-reworded bug reports contain confident but inaccurate root-cause guesses; agents erode shared team understanding of systems. — [lucumr.pocoo.org](https://lucumr.pocoo.org/tags/vibecoding); [Simon Willison tag page](https://simonwillison.net/tags/armin-ronacher/)
- [PRACTITIONER] Ralph-style loops fail on legacy codebases and ambiguous requirements. — [The Register](https://www.theregister.com/2026/01/27/ralph_wiggum_claude_loops/)
- [EVIDENCE, contested] METR's July 2025 RCT: 16 experienced OSS developers were 19% slower with AI tools while believing they were faster. The Feb 2026 follow-up is reported inconsistently: one source says returning developers still showed ~-18% (CI -38% to +9%) and METR treats it as unreliable because 30-50% of developers refused the no-AI arm; another reports 4-18% speedups among agentic-tool users. METR labels the 2025 result as historical. Primary METR post not retrieved — verify before citing figures. — [particula.tech](https://particula.tech/blog/metr-reversed-19-percent-slower-ai-coding-study); [codercops](https://blog.codercops.com/blog/ai-coding-productivity-2x-not-10x-metr-2026); [scienceblog](https://scienceblog.com/t-a-randomized-trial-by-metr-found-that-experienced-developers-completed-real-coding-tasks-19-slower-when-allowed-to-use-ai-tools-yet-afterwards-they-estimated-on-average-that-ai-had-made-them-20-fast/)
- [PRACTITIONER] Bloated, overlapping toolsets/MCP servers degrade agent behavior; rewriting one tool description cut task time 40% in Anthropic's tests. — [Anthropic: Effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents); [Anthropic: Multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system)

### Inferences
- Superseded advice: (a) "dump everything relevant into context up front" → replaced by JIT retrieval/progressive disclosure; (b) "keep correcting in the same chat" → replaced by reset-with-better-prompt; (c) "review all generated code line by line" as the primary control → shifting to reviewing plans plus automated/independent verification; (d) approve-every-action permissions → sandbox + auto/classifier modes.
- Perceived vs. measured productivity gaps (METR) mean experts' self-reported speedups (BAML, Ralph, Gas Town) should be read as existence proofs in favorable settings, not general estimates.
